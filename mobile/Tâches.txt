Elle réconcilie les paiements bloqués en "pending" depuis plus de 20 minutes (les marque "failed" si aucun webhook n'est jamais arrivé).

Configuration requise sur cron-job.org :

Méthode : GET
Fréquence : toutes les 5 minutes
En-tête HTTP obligatoire : x-cron-secret: <valeur de INTERNAL_API_SECRET>

Sans cet en-tête exact, l'appel renvoie 403 forbidden — la route est protégée pour que n'importe qui ne puisse pas la déclencher. Assure-toi que INTERNAL_API_SECRET est bien défini sur Vercel (actuellement change_me dans .env.example, donc à générer une vraie valeur secrète si ce n'est pas déjà fait) et que tu mets exactement la même valeur dans la configuration cron-job.org.

iOS préparé à l'avance : permissions système (caméra, position, micro) déclarées en français — sans ça l'app aurait planté au premier accès sur iPhone.

Sur le GoogleService-Info.plist — pourquoi je ne peux pas le faire à ta place

Ce fichier contient de vraies clés générées par Firebase pour ton app iOS précise. Bonne nouvelle en le vérifiant : une app iOS est déjà enregistrée côté Firebase (le code la référence déjà), donc pas besoin d'en recréer une — juste télécharger son fichier :

Va sur https://console.firebase.google.com/project/livra-efb01
Paramètres du projet (roue dentée) → onglet Général
Dans "Vos applications", trouve l'app iOS (bundle ID com.example.livra)
Clique Télécharger GoogleService-Info.plist

Sur le Mac ensuite, une fois flutter pub get lancé :

Ouvre ios/Runner.xcworkspace dans Xcode (jamais le .xcodeproj)
Glisse le fichier téléchargé dans le groupe Runner (à côté de Info.plist)
Coche "Copy items if needed" et "Runner" comme target
flutter build ios (ou lance depuis Xcode)

⚠️ Ne renomme pas le bundle ID (com.example.livra) sans me le dire — il doit rester identique à ce qui est enregistré côté Firebase, sinon rien ne s'authentifiera.
